# Phase 3: Rust core

## Goal
The backend foundation: environment, database, config, and the IPC conventions every later feature uses.

## Depends on
Phase 0.

## In scope
- **Login-shell env resolver:** run `zsh -ilc env` once at startup, cache, apply to every spawned child. Fall back to a sane PATH if it fails or times out (5s).
- **SQLite** via `sqlx` (or `rusqlite`) with versioned migrations. Initial tables: `projects`, `workspaces`, `sessions`, `events`, `messages`, `todos`, `checkpoints`, `ports`, `kv`.
- **Settings:** parse and merge `settings.toml` at the three levels (user, project, local override) with `serde`. Schema-validated, unknown keys preserved.
- **IPC conventions:**
  - Commands for request and response, returning a typed `Result<T, AppError>`.
  - Tauri `Channel` for high-volume streams.
  - `AppError` serialises to a stable `{ code, message, details }`.
- **Type sharing:** generate TypeScript types from Rust (`specta` or `ts-rs`) so the frontend never hand-writes them.
- **Logging:** `tracing` to a rolling file in the app support dir, with a redaction layer for env values.
- **Process registry:** record child pids in the DB for orphan cleanup.

## Out of scope
Git, workspaces, agents, PTYs. Only the plumbing.

## Deliverables
- `apps/desktop/src-tauri/src/{env,db,settings,error,ipc}/`
- A `get_app_info` command returning version, data paths, and resolved PATH summary.
- Migration `0001_init.sql`.
- Unit tests for settings merge and env parsing.

## Technical notes
- Open the DB in WAL mode. Single writer connection, small read pool.
- Store timestamps as UTC unix ms integers.
- IDs are ULIDs (sortable, no collisions).
- `events` holds raw harness JSON, `messages` is a normalised projection. Both are created now, filled in phase 8.
- Never log values of environment variables. Log key names only.

## Done checklist
- [ ] App launched from Finder (not terminal) resolves `claude`, `gh`, `git`, `node`
- [ ] DB is created on first launch and migrates on upgrade
- [ ] Settings merge order is tested
- [ ] TS types are generated by one command
- [ ] Logs contain no env values
- [ ] `cargo test` passes

## Manual test script
1. Build a release bundle, open it from Finder, call `get_app_info`, confirm `claude` is found.
2. Delete the DB file, relaunch, confirm it is recreated.
3. Put conflicting keys at all three settings levels, confirm precedence.
4. Grep the log for a known env value, confirm it is absent.
